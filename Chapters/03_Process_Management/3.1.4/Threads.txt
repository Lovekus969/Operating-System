Threads
The process model discussed so far has implied that a process is a program that
performs a single thread of execution. For example, when a process is running
a word-processor program, a single thread of instructions is being executed.
This single thread of control allows the process to perform only one task at a
time. 

Q1. What is a thread? How is it different from a process?
 Answer: A thread is the smallest unit of execution within a process.
                      Process vs Thread
| Process                     | Thread                    |
| --------------------------- | ------------------------- |
| Heavyweight                 | Lightweight               |
| Own memory space            | Shares process memory     |
| One or more threads         | Single execution unit     |
| Context switch is expensive | Context switch is cheaper |

Q2. Why did early process models support only a single thread?
Answer:  Early operating systems:
          Had single-core CPUs
          Executed one task at a time
          Did not require concurrency within a program
          Thus, a process was assumed to perform only one sequence of instructions.
Q3. What limitation exists in a single-threaded process?
Answer:
        A single-threaded process can:
           Perform only one task at a time
        Example:  In a single-threaded word processor:
            User cannot type
            While spell check is running
Q4. How do threads improve program responsiveness?
Answer:
  Threads allow:
  
      Multiple tasks to run concurrently
      One thread to handle user input
      Another thread to perform background computation
  
  Example:
    Typing text while spell checker runs
  
  📌 This improves user experience and performance.

Q5. Why are threads especially useful on multicore systems?
Answer:
         On multicore systems:
             Each core can run a separate thread
             Threads execute in parallel
          This leads to:
             Faster execution
            Better CPU utilization
            True parallelism (not just time-sharing)

Q6. Explain multithreading using a word processor example.
Answer: A multithreaded word processor may use:
          Thread 1 → User input handling
          Thread 2 → Spell checking
          Thread 3 → Auto-saving
          These threads run concurrently, allowing the program to perform multiple tasks simultaneously.
Q7. How does multithreading affect the Process Control Block (PCB)?
Answer:
       In a multithreaded system:
              The PCB is expanded
       It stores:
              Process-level information
              Thread-level information for each thread
        Each thread has:  
              Program counter
              Register set
              Stack
Q8. Does each thread have its own memory? Explain.
Answer: No.
  Threads share:
    Code segment
    Data segment
    Heap
  Each thread has its own:
    Stack
    Registers_triangle
    Program counter
  Sharing memory makes communication fast but requires synchronization.
Q9. What system-level changes are required to support threads?
Answer:
To support threads, the OS must provide:
  Thread scheduling
  Thread synchronization mechanisms
  Thread creation and termination
  Modified PCB structure
  These changes increase OS complexity.
Q10. Why are threads considered lightweight?
Answer:
       Threads are lightweight because:
       They share memory and resources
       Creation and switching is faster than processes
       Less overhead
Q11. Can threads exist without processes?
Answer:
      No.
      A thread must belong to a process.

     ------------------------------------------------------Degree of Multiprogramming-------------------------------------------------------------------------------
Definition: The degree of multiprogramming is the number of processes currently loaded in main memory.
         Why Multiprogramming Is Needed
             A single process may wait for I/O
             CPU would remain idle during this wait
             Multiprogramming keeps CPU busy by switching to another process
